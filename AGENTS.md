# AGENTS.md

Rules for anyone working in this repo, including AI agents. Read this before changing anything.

## This repo is public

Everything committed here, including git history, branches and PR text, is public for good. Deleting a file later doesn't undo that. **If you're unsure whether something is private, leave it out and ask.**

### Never add

- **Photos**, in any form: real images, thumbnails, screenshots of the running app with real photos, or base64 copies
- **Names and contact details:** friends' or voters' names, usernames or email addresses, and who is in which group
- **Identity data:** OIDC `sub` values, voter hashes, session tokens, or database files and dumps
- **Secrets:** client secrets, the voter hash secret, API tokens, private keys, `.env` or `.tfvars` files. Example values must be obviously fake
- **Details of the owner's network or infrastructure:** internal IP addresses and ranges, cluster names, node names and hardware
- **Links or IDs from any private service**, such as a photo library
- **Personal context**, such as why the owner is running a poll, or real poll titles and photo descriptions

This also applies to code comments, test data, examples, logs pasted into issues, commit messages and PR descriptions.

### Do this instead

- **Test images are generated by code** (`internal/testimg`). No image files are checked in, and `.gitignore` and CI both block them.
- **Never send real photos anywhere as part of testing**, including to an LLM. Use generated images only.
- **Example configuration** uses `example.com` and placeholder values.
- **Deployment config** (Kubernetes manifests, Terraform, network rules) lives in a separate private repo. Don't add it here.
- **Check your diff before committing.** CI runs a secret scan and blocks image and database files, but it can't recognise a name or a private detail.

## What this is

A small website where one owner uploads photos and chosen people rate them from 1 to 5 stars. Login uses OIDC. It's pure Go and server-rendered HTML with plain CSS, and has no JavaScript and no frontend build step. Please keep it that way, and raise it first if you think something needs more.

## Rules the code must keep

These are the point of the project. Tests cover them, and a change that breaks one is wrong even if the tests are updated to match.

- **Ratings aren't linked to people on the site.** No page shows who gave which rating, including the owner's pages. Results show only each item's average and number of ratings, never a breakdown by score.
- **Voters don't see totals until a poll closes.** The owner can see them live.
- **Never log a voter and a rating together.** Request logs use the route pattern, not the real path. Don't log `sub` values, hashes, scores, poll or item IDs, or filenames.
- **Ratings store only the keyed hash** `HMAC(secret, poll ID + sub)`, with no timestamps and no rowid, so stored order can't reveal who voted when. `sub` is never written to disk.
- **Never store or serve an uploaded file as it arrived.** Every image is decoded, resized and re-encoded, which removes metadata such as GPS location. Original filenames aren't stored.
- **Every route declares its access level** in the table in `internal/web/server.go`, and tests check every entry. Don't register routes any other way.
- **Images are served only through the handler that checks login and role**, and there is no public file folder.
- **Don't describe voting as fully anonymous.** The owner could work out who rated what, using the hash secret and the user list. The voting page says so.

## Working here

```bash
go test ./...              # all tests
go vet ./...
gofmt -l .                 # should print nothing
go run ./cmd/devserver     # local app with a fake login and generated photos
```

- Use the standard library first, and raise any new dependency before adding it.
- Work on a branch and open a PR. The owner merges.
